組込みシステムにおける各ハードウェア

CPU

  • フェッチ、デコード、実行を司る
  • パイプライン化：処理を分割して並行処理
    • ex: 処理が1CLKとすると、1命令は3CLK
    • 単一処理の実行時間(レイテンシ)は変わらないが、複数処理の処理効率(スループット)を向上できる
  • RISCは単純な命令で構成される
    • 命令長が固定であるため、パイプライン化で有利
    • 消費電力が比較的小さい
  • CISCは複雑な処理を1命令で表せる
    • 命令長が可変長であるため、パイプライン化で不利
    • 高性能だが、消費電力も大きい

マルチコア

  • ホモジニアスマルチコア：同じ種類のプロセッサを使用

  • ヘテロジニアスマルチコア：複数の種類のプロセッサを使用

  • ハードウェアアクセラレーション：CPU以外の演算デバイスを組み合わせることで、処理性能の向上を目指す

  • 実装では、リソース管理が難しい

    • コア内部での排他制御だけではなく，コア間での排他制御も必要
    • 非対称型ではメモリ保護も…

演算デバイスの比較 - MPU：CPUとメモリ、I/O周りを統合したもの - GPU：高次元の信号処理に特化したプロセッサ、汎用並列演算能力が高い。 - FPGA：回路を自由に構成できるLSI。低周波数で特化した並列演算を構成できる。 - ASIC：カスタムIC、作り直すコストは高いがかなり特化した処理ができる - 量産性がコストパフォーマンスに影響する

  • 消費電力：MPU < … < ASIC
  • 開発コスト：MPU < … < ASIC
  • 性能：MPU < … < ASIC

ヘテロジニアスの構成: - 組込みでは、ヘテロジニアスマルチコアが主流 - 実行する処理の特性や，システムに求められる性能・機能にあったデバイスを選定したほうが，消費電力を抑えることや，コストダウンに繋がるため - また、特定の演算量が多い処理を高速化するため - 結局、目的によって最適な組み合わせを見つける —

  • 構成例1：高速CPUにLinux、低速CPUにRTOS
    • 直接ハードウェアを制御するところはRTOSに任せる
    • リアルタイム処理側は高いセキュリティが求められる
  • 構成例2：CPU+FPGA
    • 画像処理の前処理にFPGAを利用
  • 構成例3：CPU+ASIC
    • 携帯電話など。ASICに電波処理をさせる

ホモジニアスにおけるコア - 対称型：複数コア1OS、わかりやすく、ソフトプラットフォームが単一 - 非対称型：複数コア複数OS、わかりずらいが、コアごとに特徴をもたせやすい - Inttel 12th latter, Snapdragon

メモリ

  • ROM：不揮発性、電源供給がなくてもデータ保持可能(低速)
  • RAM：揮発性、電源供給がないとデータが消える(高速)
  • メモリにはアドレスが割り当てられる。
    • この割り当て範囲の定義をアドレス空間という
  • 高速アクセスができないと、システムのボトルネックとなる
    • MPUは頻繁にメモリアクセスする
    • 命令実行時間より、データ読み出しに時間がかかるのでオーバヘッド

メモリの種類

  • DRAM：コンデンサ、大容量、低価格、低速
    • 放置すると放電されるためリフレッシュ
    • メモリアクセス時に放電されるためプリチャージ
    • プリチャージによって消費電力が大きくなる。
  • SRAM：FF、小容量、高価格、高速
    • キャシュに使用

キャッシュメモリ - MPUと主記憶の間に主記憶より高速なメモリを設置することで、メモリアクセス性能を高める - 主記憶アクセス時のデータ・命令をキャッシュにも保存する - ヒット：キャッシュにデータがあると性能向上 - ミスヒット：キャッシュにデータがないと性能低下 - キャッシュにないので主記憶にアクセス - ミスヒットのタイミングは予測しづらい - 整合性の問題：キャッシュのみでデータ更新すると、主記憶との整合性がなくなる - ライトバック方式：主記憶を更新しなければならないタイミングでキャッシュのデータを主記憶に書き込む - 主記憶アクセスを低減できるが、複雑な制御が必要 - ライトスルー方式：適宜、主記憶に書く - 単純だが、アクセス回数は増加する

DMA - MPUを経由せず、「直接」アクセスする - NICからのデータなど - DMAコントローラはバスを専有可 - バースト転送：全データ転送まで使用権を離さない、アドレス指定が最初だけなので、高速にデータ取得可能 - バイト転送：1バイトずつ、確保と解放をする(ラウンドロビン的に)

MPU - 論理アドレスを使用するためのもの - 動的確保と仮想記憶 - メモリ保護ができる

物理世界とのやりとり

ADC

  • 標本化：時間軸方向の離散化
    • 標本化定理：対象の信号の周波数の2倍よりも高い周波数で標本化すると，正確にデジタル信号に変換できる
  • 量子化：電圧(振幅)方向の離散化
    • 分解能：量子化に使えるビット数で精度が決 ## PWM(パルス幅変調)
  • モータ制御で使用
    • 実質「電圧」が低下するため，速度だけではなく力（トルク）も落ちる．
    • モータの特性にもよるため，デューティ比に対して比例関係で「速度」のみが減速するわけではない．
  • 1周期の矩形パルスのうち，Hiレベルが占める割合をデューティ比として変動させる
  • デューティ比：1周期のうち，Hiレベルの時間の割合

チャタリング

  • SWで発生する振動
  • コンピュータは気づくので対策がいる
  • ソフトウェア的：スイッチの判定の直後に短いタイマを挿入
  • ハードウェア的：コンデンサや，論理ゲートIC

ノイズ対策

  • ADCの結果はノイズが入ってる可能性がある

フィルタリング - ハイパス：特定周波数より低い周波数をカット - ローパス：特定周波数より高い周波数をカット - バンドパス：特定の周波数範囲のみパス

  • ハード的：RLCで作る
  • ソフト的：離散フーリエ変換

コンパウンディング(コンプレッサ) - 振幅の大小の差を縮め、例えば音であれば聞きやすさを向上する。

コンボリューション(畳み込み) - 特定の特徴を弱めたり，強めたりすることができる．

ヒステリス特性 - 現在の入力と過去の入力を使って，出力を決める特性 - しきい値処理で細かい値で揺れる場合に有効 - シュミットトリガ：しきい値を2つ持つことによって，細かな入力電圧の変化による，出力結果の振動を防ぐことができる． - 例えば、HighになるときとLowになるときでしきい値を変える

精度

  • 高精度で測定したら良いこともあるが、ノイズもその分増えるので注意が必要となる。

開発環境

  • 基本的には非組込みのソフトと同じようなことはできることが多い
    • 主に見るのは性能とメモリのバランス
    • 結果がわかりにくので、デバッガやエミュを活用する
  • mapファイル解析：領域にどのようなデータが多いのかを確認できる
  • コールグラフ：関数の呼び出し関係を図示する。
    • 関数呼び出し回数が多いとスタックを消費
  • 性能プロファイリング：関数が実行されるのにかかる時間やメモリアクセスしている時間などを可視化

OS

  • 汎用OS：IoTの実現、USBドライバの利用などで便利
    • ROS(ミドルウェア)：ライブラリや通信方式の定義
  • RTOS：軽量かつリアルタイム性を保証
    • 資源の抽象化や仮想化は不十分(タスクのみ抽象化してる)
      • プログラムサイズを小さくするため
    • ハードウェア依存部については適宜移植する必要がある
    • 汎用OS型：応答時間は遅いが、機能が豊富->意識しなくていい部分が多い
    • リアルタイムカーネル型：応答時間は早く、カーネルサイズは小さいが、機能は限定的
  • コンテキスト：タスクが実行される環境
    • タスクコンテキスト：OSが管理するもの
    • 非タスクコンテキスト：割り込みなどOSの想定外のタイミングで実行される
  • プリエンプトとディパッチ
